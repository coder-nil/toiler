# macOS 标题栏实时毛玻璃

## 实现边界

- `crates/toiler-desktop/src/native_titlebar.rs` 负责一个具名的
  `NSVisualEffectView`，以 `BehindWindow` 模式由系统实时合成窗口后方内容。
- 视图放在 WebView 下方，不把文字和按钮作为材质层的子视图，不修改窗口或材质层
  alpha，不截屏、不轮询桌面，也不缓存背景图片。
- 材质仅覆盖顶部 42 逻辑点。原生自动布局与窗口缩放事件共同保持位置、宽度，
  重复更新复用同一个视图；页面就绪后再次检查当前 contentView，避免材质留在旧容器。
- `frontend/public/native-titlebar.js` 在页面就绪和主题变化时同步原生外观，
  不承担背景采样或刷新。CSS 顶部透明，正文仍绘制不透明背景。
- 移动窗口或后方动画的刷新交给 macOS 合成器，不通过定时销毁、重建材质视图来刷新。
- 其他平台保持原样；此实现不是网页 `backdrop-filter`。

## 诊断

应用日志中的“实时标题栏材质”记录实际视图数量、区域、混合模式、活跃状态、
alpha、是否关联窗口、窗口不透明标记、页面深浅色、实际原生主题，以及系统
“降低透明度”状态。页面就绪后应出现“页面深色=Some(false/true)”的同步日志；
如果只有建窗时的 None，先检查 IPC 是否被拒绝，不要直接改材质或透明度。

`sync_titlebar_appearance` 必须同时列入 `build.rs` 的命令清单和
`capabilities/default.json` 的 `allow-sync-titlebar-appearance` 权限。
只注册 Rust 处理函数仍会被应用 ACL 拒绝，导致浅色网页叠在深色原生材质上。

正常应为：数量 1、alpha 1、已关联窗口 true、窗口不透明 false；模式为
BehindWindow，状态为 Active（绑定的日志可能显示对应枚举数值）。
区域应位于窗口顶部，高度为 42 逻辑点。

如果系统开启“降低透明度”，日志会给出警告。应用尊重辅助功能设置，不自动关闭它。
原生材质的底色、模糊强度和更新策略仍由 macOS 控制。

## 手动动态验收（不能用编译通过代替）

重新运行新编译的 `target/release/toiler-desktop` 后：

1. 在另一个窗口播放色彩变化明显的视频或动画，把 Toiler 标题栏放在其上方。
2. 保持 Toiler 不动，确认标题栏色块随后方画面持续变化，而非只在移动时更新。
3. 保持后方画面不动，拖动 Toiler，确认采样区域随窗口位置变化。
4. 改变窗口大小、切换全屏、切换浅色/深色主题，确认顶部没有错位、留下旧材质或
   重新变成 PNG 纹理；正文、标题文字与按钮保持清晰。
5. 检查窗口失焦时的背景变化、红绿灯与标题栏拖动及按钮点击。

测试记录应区分自动化测试、运行时诊断与上述实际视觉验收。仅存在透明度、
或背景文字仍清晰可读，均不能单独作为毛玻璃效果通过的依据。
